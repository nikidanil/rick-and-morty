# 🚀 Проект: Rick and Morty Wiki

## 🎯 Цель репозитория

Цель данного проекта — **практическое применение возможностей React Router v6** в современном React-приложении (React 19), а также реализация продвинутой пагинации с кэшированием и сортировкой.  
Проект демонстрирует вложенную навигацию, динамические маршруты, обработку 404 и синхронизацию состояния с URL.

Кроме навигации, проект реализует:

- Работу с публичным API Rick and Morty (вместо локального `json-server`)
- Управление состоянием авторизации через **React Context (React 19)**
- Приватный роутинг с защитой доступа к страницам
- Постраничную загрузку данных с поддержкой **infinity scroll**
- Кэширование метаданных для оптимизации запросов
- Сортировку данных по возрастанию и убыванию
- Поддержку **PWA (Progressive Web App)** с возможностью установки на устройство
- Работу в **офлайн-режиме** с отображением кэшированных данных и резервной страницы
- Повторное использование компонентов и хуков
- Корректную типизацию (TypeScript)
- Чистую и масштабируемую архитектуру по принципам **FSD**

---

## 🧩 Решаемая задача

### Проблема

В реальных приложениях часто требуется:

- Отображать большие списки данных без блокировок
- Подгружать новые порции по мере прокрутки (infinity scroll)
- Поддерживать сортировку без перезагрузки
- Избегать повторных запросов к API
- Обеспечивать плавную навигацию между страницами
- Ограничивать доступ к определённым страницам без авторизации
- Поддерживать состояние пользователя между действиями
- Поддерживать масштабируемую и поддерживаемую структуру кода

### Решение

Проект решает эти задачи с помощью:

- **React Router v6** — для вложенной и динамической навигации
- **React Context API (React 19)** — для управления аутентификацией
- **Кастомный хук `useRickAndMortyData`** — для эффективной пагинации и кэширования
- **Компонент `SortPanel`** — для универсальной сортировки
- **Intersection Observer** — для автоматической подгрузки при прокрутке
- **Архитектура FSD (Feature-Sliced Design)** — для масштабируемой и понятной структуры
- **shadcn/ui** — для реализации продвинутых UI-компонентов, включая `Select`
- **PWA с поддержкой офлайн-режима** — реализована через `vite-plugin-pwa` и `Workbox`

## 🗂️ Структура репозитория (FSD-архитектура)

Проект перенесён на **архитектуру FSD (Feature-Sliced Design)**, что обеспечивает:

- Чёткое разделение ответственности
- Повторное использование слоёв
- Лёгкий рефакторинг и масштабирование
- Независимость фич

Основные слои:

- **`shared/`** — общие утилиты, типы, UI-компоненты (например, `useRickAndMortyData`, `types`, `ui/`)
- **`entities/`** — бизнес-сущности (`hero`, `location`, `episode`) с их данными и хуками
- **`features/`** — функциональные возможности (`auth`, `sorting`) с логикой и UI
- **`pages/`** — страницы, компонующие фичи и сущности
- **`widgets/`** — составные компоненты уровня страниц (например, `MainLayout`)

Примеры:

- `entities/hero` — модель, типы и хуки для персонажей
- `features/auth` — авторизация, `AuthProvider`, `PrivateRoute`
- `features/sorting` — сортировка через `SortPanel` и `useSortParams`
- `shared/ui` — переиспользуемые компоненты, включая **`Select` из shadcn/ui**

## 🔧 Ключевые особенности реализации

### 🎣 Кастомный хук `useRickAndMortyData`

Хук `useRickAndMortyData` — это **универсальное решение для пагинации данных из API Rick and Morty** с поддержкой сортировки и кэширования.

#### Основные возможности:

- **Автоматическая подгрузка по прокрутке** (`infinity scroll`)
- **Поддержка сортировки**:
    - `asc` — данные загружаются с первой страницы
    - `desc` — данные загружаются с последней страницы (обратная пагинация)
- **Кэширование метаданных**:
    - Общее количество элементов и страниц сохраняется в глобальном `Map`
    - При повторном использовании хука по той же категории — метаданные не запрашиваются повторно
- **Оптимизация запросов**:
    - Загрузка данных начинается только **после получения метаданных**
    - Используется `AbortController` для отмены "зависших" запросов
- **Безопасное управление состоянием**:
    - При смене категории или сортировки — страница сбрасывается (если данные не загружены полностью)
    - Состояние обновляется только при валидных условиях

### 🌐 Поддержка PWA и офлайн-режима

Проект реализует полноценный **Progressive Web App** с возможностью установки на устройство и работой без интернета.

#### Особенности:

- **Автоматическое обновление**: `registerType: 'autoUpdate'`
- **Офлайн-страница**: `/offline.html` показывается при отсутствии интернета и отсутствии кэша
- **Кэширование API**: данные с `rickandmortyapi.com` кэшируются с политикой `StaleWhileRevalidate`
- **Кэширование изображений**: стратегия `CacheFirst`, сроком до 30 дней
- **Офлайн-оболочка**: главная страница и статические ресурсы кэшируются для быстрой загрузки
- **Поддержка навигации без интернета**: при наличии кэша пользователь может просматривать загруженные ранее данные

#### Стратегии кэширования:

- **Сетевые запросы**: `StaleWhileRevalidate` — показывает кэш, обновляет в фоне
- **Изображения**: `CacheFirst` — максимальная скорость загрузки
- **Навигация**: `NetworkFirst` с fallback на `/offline.html` при полном отсутствии сети

---

#### Принцип работы:

1. **Загрузка метаданных**:
    - При первом вызове хука для категории (`character`, `location`, `episode`) отправляется запрос к API за первой страницей.
    - Из ответа извлекаются `info.count` и `info.pages`.
    - Данные сохраняются в `metaCache` (глобальный кэш) и используются повторно.

2. **Загрузка данных**:
    - После получения метаданных запускается загрузка содержимого.
    - При `sortOrder: 'desc'` страницы запрашиваются в обратном порядке: `totalPages - page + 1`.
    - Данные добавляются к существующему массиву.

3. **Подгрузка при прокрутке**:
    - Функция `loadNext` увеличивает `page`, что запускает новый запрос.
    - Используется в связке с `IntersectionObserver` (в `HeroesPage` и др.).

4. **Повторное использование**:
    - Если хук снова вызывается с той же категорией — метаданные берутся из кэша.
    - Это предотвращает лишние запросы и ускоряет работу.

#### Пример использования:

```tsx
const { data, loading, error, hasMore, loadNext } = useRickAndMortyData<Hero>('character', 'asc');
```

## 🛠️ Как запустить и использовать

### 1. Установка зависимостей

```bash
npm install
```

### 2. Запуск приложения

```bash
npm run dev
```

### 3. Доступные маршруты

| Маршрут         | Тип доступа | Описание                         |
| --------------- | ----------- | -------------------------------- |
| /               | Публичный   | Главная страница                 |
| /login          | Публичный   | Страница входа                   |
| /heroes         | Приватный   | Список персонажей (требует вход) |
| /heroes/1       | Приватный   | Детали персонажа с ID=1          |
| /locations      | Приватный   | Список локаций                   |
| /locations/1    | Приватный   | Детали локации                   |
| /episodes       | Приватный   | Список эпизодов                  |
| /episodes/1     | Приватный   | Детали эпизода                   |
| /any-wrong-path | Публичный   | Страница 404                     |

### 🎨 Использование shadcn/ui

Для реализации компонента `Select` использована **UI-библиотека shadcn/ui**, которая предоставляет:

- Высококачественные, доступные и кастомизируемые компоненты
- Интеграцию с Radix UI и Tailwind CSS
- Поддержку тем (светлая/тёмная)
- Анимации, фокусы, состояние загрузки

Компонент `Select` был интегрирован в слой `shared/ui` и используется в `SortPanel` как часть фичи `sorting`.

Преимущества:

- Семантическая доступность
- Полная поддержка клавиатуры
- Гибкая стилизация через `className` и CSS-переменные
- Лёгкая кастомизация под дизайн проекта

### 🔐 Управление авторизацией (React 19)

Проект использует **новые возможности React 19**:

- `<AuthContext value={...}>` — новый синтаксис передачи значения в контекст (вместо `.Provider`)
- `use(AuthContext)` — новый рекомендованный способ чтения контекста
- `AuthProvider` — оборачивает всё приложение, обеспечивая единое состояние

**`PrivateRoute`** — компонент-обёртка, который:

- Проверяет наличие пользователя
- При отсутствии — перенаправляет на `/login` с сохранением целевого маршрута

---

### 📑 Страницы и навигация

- **`MainLayout`** — общая обёртка с навигационной панелью
- **`HeroesPage`, `LocationsPage`, `EpisodesPage`**:
    - Используют `useRickAndMortyData` для загрузки данных
    - Применяют `SortPanel` для управления порядком
    - Подгружают данные при прокрутке через `IntersectionObserver`
- **Детальные страницы (`HeroPage` и др.)**:
    - Используют `useParams()` для получения `id`
    - Загружают детали по ID из API
- **`Login`**:
    - Позволяет ввести логин и войти
    - После входа перенаправляет на предыдущую страницу
- **`NotFoundPage`**:
    - Обрабатывает все несуществующие маршруты

---

### 🛠️ Функциональность

**Авторизация:**

- При попытке зайти на `/heroes`, `/locations`, `/episodes` без входа — редирект на `/login`
- После входа — автоматический возврат на запрашиваемую страницу
- Данные пользователя хранятся в контексте (не в `localStorage` — для простоты)

**Сортировка:**

- На страницах списков — можно выбрать "Сначала новые" / "Сначала старые"
- Параметр `?sort=asc` сохраняется в URL
- При `desc` — параметр удаляется (чистота URL)

**Навигация:**

- Через панель в `MainLayout`
- Поддержка кнопки "Назад" в браузере
- Активные ссылки подсвечиваются

**404:**

- Любая несуществующая страница → `NotFoundPage` с цитатой Рика
